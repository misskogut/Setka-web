# SETKA Genesis · v34 CURRENT

Это отдельный снимок связной пары SETKA на точке 2026-08-31.

## Поверхности

- `index.html` — точная пользовательская поверхность `standalone-v34.html`.
- `admin.html` — точная административная поверхность `standalone-admin-v34.html`.

Обе поверхности и все их JS/CSS-зависимости зафиксированы из исходного commit `872d292913281844e3cc8e2cb9908b225aaaecd8` и лежат внутри этого каталога. Исходные файлы в корне `Setka-web` не изменяются этим снимком.

## Связка в точке СЕЙЧАС

Пользовательский фронт синхронизируется через `setka-standalone-v34`; административный bridge читает тот же backend-контур. Поэтому фронт и админка являются двумя поверхностями одной текущей MVP-системы, а не двумя независимыми прототипами.

## Режим доступа

На этом этапе новый access/ID gate не добавляется. GitHub Pages остаётся открытым по прямой ссылке. Встроенные исследовательские ID-сущности текущего MVP сохранены как часть существующей функциональности, но не используются как внешний барьер входа в этот проект.

## Genesis-правило дальнейшей разработки

Не пересобирать UI заново ради архитектуры. Развивать эту пару параллельно: любое новое пользовательское действие сначала получает общий backend/event contract, затем одновременно отражается на фронте и в административной проекции.

Неизменяемые требования SETKA Genesis:

1. Сущность имеет устойчивую identity.
2. История дописывается, прошлое не переписывается незаметно.
3. Каждая запись имеет provenance и автора/источник.
4. Причина, исполнение, validation и acceptance не смешиваются в один статус.
5. Состояние выводится из доказанных событий; интерфейс не является источником истины.
6. Новая функциональность не считается завершённой, пока её результат нельзя увидеть и восстановить с обеих сторон связки.

## Следующий режим

Этот каталог — рабочая база для дальнейшей параллельной разработки frontend ↔ backend ↔ admin без изменения геометрии текущего MVP до отдельного решения о редизайне.
