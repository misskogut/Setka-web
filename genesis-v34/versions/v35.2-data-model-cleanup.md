# SETKA Admin Evolution v35.2 — Data Model Cleanup

Status: canonical checkpoint
Date: 2026-08-25

## Purpose

v35.2 is the architectural cleanup after Evolution v35.1. It does not create a second analytics reality; it defines one canonical entity graph and makes dashboards consume metric projections from that graph.

## Canonical sources

- Pattern/config gameplay time → `prototype_v35_pattern_exposures` only.
- Current saved heart → `prototype_v35_favorites` only.
- Stable default participant number → `prototype_v35_participant_ordinals`.
- New app visits → `prototype_v35_visits`.
- Outcome vs exploration → explicit canonical Session type; exploration is never outcome evidence.
- UX path / cursor / taps → RAW Replay while retained, then Replay Digest.
- Participant / Pattern / exact-config dashboards → derived v35 fact tables rebuilt from the canonical sources.

## Pattern Exposure

One row is one uninterrupted period in which one exact canonical PatternConfig is actually visible in gameplay.

Contexts:
- `free`
- `measured`
- `after_feedback`
- `exploration`

Changing config, leaving gameplay, changing session/context, hiding the page, or closing the page closes the exposure. `session.usage` remains only as a backward-compatible projection for existing session UI.

Historical formal `session.usage` rows were backfilled because they were already gated by gameplay. Historical free-Replay config durations were deliberately NOT backfilled, because retained app state could falsely count Library/Today time as pattern viewing.

## Metric rule

A real entity exists once. Different dashboards are metric slices, not duplicate entities.

`Metric = Entity × Scope × Context × Period × MetricDefinition`

Example: global Dandelion time, one participant's Dandelion time, Dandelion in outcome sessions and Dandelion for one request are different metric states of the same `Pattern:dandelion`.

## Outcome methodology

Only `measured` exposure time participates in primary pre→post association. Each Pattern/PatternConfig is weighted by its share of measured exposure time in that outcome session. `after_feedback` and `exploration` are excluded from the primary outcome association.

## Runtime/API cleanup

- Evolution uses one active analytics API: `setka-admin-evolution-v35`.
- The old client fetch-router is no longer loaded by Evolution.
- Pattern / Exact-config / Community uses the same canonical Evolution API.
- v35 facts refresh during semantic participant sync.
- RAW Replay is no longer a source of pattern/config product time.

## Current legacy boundary

Old Replay rows created before canonical `visitId` remain valid UX history but have no trustworthy Visit relation. They are treated as legacy visits rather than assigned to fabricated visits retroactively.

Old exploration session-index rows have been normalized so `planned_seconds` is null. New sync enforces this automatically.

## Audit at checkpoint

At the checkpoint audit:
- no duplicate logical keys were found in Favorite, Pattern Fact, Config Fact, Exposure ID or Visit ID groups;
- v35 canonical config keys had zero noncanonical rows in exposures/favorites/config facts;
- Participant Facts exposure counts and durations matched canonical Pattern Exposure rows for every current device;
- Pattern Facts exposure counts and durations matched Pattern Exposure aggregates;
- stable participant ordinals were unique and covered current devices;
- syntax check and GitHub Pages deploy were successful for the latest v35.2 runtime.
