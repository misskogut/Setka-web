# SETKA 1.4.1 · состояния и живые миниатюры

Родитель: `2dbf4dcc7d425d156c114e059fddf6f37ef3d3a2` (1.4.0).
Только мобильная SETKA с паттернами; прежняя админка и VERSTAK независимы.

## Исправление сохранения

Воспроизведённая ошибка: две вкладки загружают одну локальную копию; после добавления
состояния в первой вкладке событие из второй сохраняло старый пустой список поверх него.
Сервер также заменял архив устройства целиком, позволяя старому запросу стереть выбор.

Локальное сохранение теперь объединяет состояния и отметки по точным ID в пределах
одной копии (`createdAt`). Новые изменения имеют `updatedAt`; выбор другой копии или
сброс локальной истории не объединяет разные копии по предположению. Событие storage
обновляет открытую карточку только при фактическом изменении состояний.

Серверный `setka_private_archive_write_v1` объединяет состояния и отметки атомарно
в конфликтующей строке PostgreSQL, удерживая блокировку записи. Пустые старые запросы
не удаляют уже зарегистрированные записи. Разный владелец устройства вызывает отказ.
История не объединяется по похожему имени. Прочие поля сохраняют прежний контракт.
Миграция `research-v1/sql/state-history-upsert.sql` добавляет только две service-only
SECURITY INVOKER функции. Существующие RLS, вход, согласия и таблицы не меняются.

Ответ API содержит подтверждённые состояния и отметки. Фронт сравнивает точное
содержимое, а не число записей или время любой синхронизации. Изменение во время
запроса остаётся ожидающим до следующего подтверждения. Успешная загрузка старого
архива не выдаётся за сохранение нового выбора.

Разные браузеры имеют разные локальные хранилища. Гостевые данные видны только
в их браузере. В другом браузере восстановление возможно через существующий вход
в тот же аккаунт и уже принятый договор хранения; новые способы входа не добавлены.
Данных, которые не были зарегистрированы или сохранились лишь в другом гостевом
браузере, сервер не выдумывает и не объявляет восстановленными.

## Визуал

Метка новых базовых паттернов: `new`; исчезновение после первого открытия прежнее.
Живые миниатюры используют числовой рендерер приложения и точные конфигурации каждой
карточки. Они не меняют выбранную конфигурацию, кадры заметок, сохранённые рецепты,
историю открытий и измеряемое время. Анимация ограничена примерно 12 кадрами/сек,
только для видимых карточек. Она останавливается в фоне, под открытой карточкой,
в игровом экране и при системном предпочтении уменьшить движение.

## Проверка и публикация

- Регрессия двух устаревших локальных записей и точного подтверждения ответа.
- Изолированный PostgreSQL: пустой старый запрос, новая версия, повтор, чужой аккаунт,
  права вызова; две параллельные записи сохраняют обе записи.
- Изолированные Chromium/WebKit: создание состояния и отметки касанием, подтверждение,
  старая вкладка, перезагрузка и другой браузерный контекст того же тестового аккаунта,
  отображение в карточке участника админки, анимация без фиктивного использования.
- В рабочую базу синтетические состояния не добавляются. После установки проверяются
  функции/права/развёрнутый API и страницы; реальный iPhone остаётся отдельной проверкой.

Архив Edge parent=12. Защита состояний совместима с прежними клиентами. Для отката UI
вернуть родительский коммит, сохранив серверную защиту и зарегистрированные данные.
