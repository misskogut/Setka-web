# SETKA — аудит связности данных (11 ноября 2026)

Проверен действующий Supabase-проект `setka-web-research` (без изменения пользовательских данных).

## Результаты
- 475 аккаунтных записей просмотра паттернов; 436 из них имеют `session_id = NULL` (допустимый свободный просмотр, не ошибка связи).
- **0** записей с заполненным `session_id`, ссылающихся на отсутствующую аккаунтную сессию.
- **0** потерянных связей: аккаунтные сессии/просмотры/избранное → аккаунт.
- **0** потерянных связей: серверные просмотры → сессии.
- **0** потерянных связей: события прослушивания → музыкальные треки.
- **0** потерянных связей: статистика треков → треки.
- **0** потерянных связей: исторические просмотры → устройства/сессии.
- **113** исторических записей избранного, относящихся к **32** устройствам, записи которых отсутствуют в реестре устройств. Данные не удалены.

## Исправление
В Supabase Edge Function `setka-research-admin-v1` опубликована версия **17**. Модель данных создаёт явную запись «Историческое устройство без метаданных» для источников с сохранённым избранным, но без карточки устройства. Эти записи не считаются подтверждёнными пользователями и исключаются из персональных метрик (`includedInMetrics:false`). Историческое избранное остаётся доступным в проекции админки.

## Ограничения
Это проверка перечисленных связей и исправление представления сирот в админке, а не доказательство полной доставки каждого фронтового события. Не проводились браузерные E2E-тесты, сквозные тесты сетевых отказов и проверка всех исторических таблиц. Полный ноль сирот во всей базе **не подтверждён**.

Повторяемые SQL-проверки: `scripts/setka-data-orphans-audit.sql`.
