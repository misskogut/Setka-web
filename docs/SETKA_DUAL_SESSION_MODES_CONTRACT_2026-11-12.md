# SETKA — два режима исследования паттернов

## Продуктовое правило — уточнение от основателя

**«Просто посмотреть»** — кнопка при открытии паттерна: свободный
просмотр без анкет и оценок состояния. Такие просмотры и их длительность
должны учитываться наравне с просмотрами во время сессий, но без
выдуманных показателей «до → после». В V2 они сохраняются без
`session_id`, а в локальном архиве связываются по `visitId`.

**«Просто исследую»** — вариант запроса/состояния **на экране запуска
сессии**, а не название свободного просмотра. Текущая внутренняя
реализация обрабатывает этот выбор как `exploration` (без анкет
«до → после»), но для общей аналитики он относится к **просмотрам
внутри сессий**, поскольку пользователь нажал «Запустить сессию».

Другие запросы («Расслабиться», «Сконцентрироваться» и т. д.) ведут к
сессии `outcome`: состояние до/после, выбранные отслеживаемые
состояния, плановая длительность и связанные измерения.

Все просмотры считаются одинаково: фактическое время, паттерны и
настройки. Каждая заметка сохраняет паттерн, время и `sessionId`
при запущенной сессии либо `visitId` при свободном просмотре.

**Названия, кнопки и переходы менять нельзя без отдельного запроса.**
Личные тексты заметок не передавать в общую обезличенную телеметрию.

## Схема аналитики

- V2 pattern_exposure: одинаковый подсчёт просмотров и длительности
  для двух режимов; session_id связывает события с сессией.
- properties.session_type: outcome / exploration — только явное
  значение от клиента; нулевое значение не заменять догадкой.
- Отдельная категория unbound: «Просто посмотреть» без session_id.
  Её нельзя смешивать с выбранным запросом «Просто исследую».
- Главная V6: «Во время сессий» = outcome + exploration;
  «Просто посмотреть» = unbound; legacy_unknown отдельно.
- legacy_unknown: у исторической записи есть session_id, но тип
  ещё не подтверждён.
- Ни одна из этих категорий не должна автоматически приписывать
  старым записям «эффективность» или медицинский результат.
- V40/V41 и V2 могут пересекаться: не суммировать уникальных
  людей без проверенной схемы идентичности.

## Приёмочные сценарии

1. «Начать сессию» → «Просто исследую» → несколько паттернов →
   одна сессия exploration, история паттернов и заметка внутри неё.
2. «Начать сессию» → запрос, состояние, длительность →
   сессия outcome, оценка до/после, связанные заметки и паттерны.
3. После обновления страницы активный тип сессии сохраняется.
4. «Просто посмотреть» не превращается в исследовательскую сессию.
5. Главная исследовательской админки V6 показывает оба режима
   без переключателей; подробности находятся в карточке паттерна.
6. Проверить на реальном устройстве отправку session_type в V2,
   а также наличие сессии/паттерна у заметки. Автоматические тесты
   не заменяют эту ручную проверку.
