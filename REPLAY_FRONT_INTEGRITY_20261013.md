# SETKA Research 1.1 — исправление Replay и проверка фронта

## Причина пустого экрана

В версии 1.0 плеер сравнивал номер исторического паттерна с номером текущего каталога. В настоящем архиве `rgb-glitch-rings` имеет поколения 1, 35 и 36. Версия 35 использовала геометрию сегодняшней «Носовой волны» под прежним идентификатором. Кроме того, некоторые исторические слепки содержат лишь часть полей `config`, хотя полный числовой рецепт сохранился в `configKey`. Отказ только из-за номера версии был ошибкой.

Добавлен проверяемый контракт восстановления рецепта и явное соответствие историческим рендерам. Исходный идентификатор и версия остаются в техническом просмотре. Неизвестная версия, отсутствующий рецепт или конфликт слепка с кодом конфигурации остаются честными пробелами. Стартовый паттерн не подставляется.

На реальных записях Supabase проверены 500 различных состояний, представляющих 1 881 зарегистрированный слепок. Все рецепты этой выборки восстановлены, включая RGB 1/35/36, дыхательные фракталы и стереоспираль. Это проверка рецептов, не доказательство полного восстановления каждой сессии.

## Воспроизведение

- Управление и временная шкала находятся над телефоном и доступны на небольшом экране.
- Есть переход к первому подтверждённому визуальному состоянию. Начало без слепка не дорисовывается.
- Восстанавливаются точные зарегистрированные параметры и кадровая точка; исходный размер экрана используется, если сохранён.
- Экран формы имеет приоритет над более старым игровым слепком. Обрабатываются зарегистрированные видимость и касания.
- Новый интерфейс воспроизводится по сохранённым геометрическим элементам, текстам, разрешённым иконкам и числовым рецептам превью. Произвольный HTML не исполняется.
- Заметка со своим неизменяемым слепком восстанавливается даже без отдельного изменяемого `state`.
- Для старых экранов без элементов честно показывается зарегистрированное название и отсутствие подробностей. Видеозаписи в базе нет.
- Шлейф анимации после перемотки зависит от предшествующей отрисовки и обозначен приблизительным. Полнота записи не повышается автоматически.

## Фронт и приватность

Существующие семь паттернов, сессии, самооценки, состояния, заметки, избранное и общественная статистика сохранены. API проекта: `gfchgaphzhxufwdhrcis`. Старые полная админка и её модули не изменены. SETKA VERSTAK не затронут.

Во фронт добавлена выключенная по умолчанию настройка «Записывать экран и касания для Replay» в разделе «Я». Она объясняет, какие данные сохраняются и кому доступны. Вводимые значения, пароли, экраны входа, восстановления и кабинета исключены. У гостя запись локальная. Передача подробной записи в личный облачный архив дополнительно требует актуального подтверждённого согласия кабинета. В общий исследовательский слой или публичное сообщество эти элементы не отправляются.

Запись ограничена 80 подробными слепками экрана; число вытесненных слепков сохраняется. Обычные числовые события продолжают храниться по существующим правилам. Никаких новых административных ключей, паролей или токенов в репозитории нет.

Исправлены ещё два нарушения данных: окончание прерванной сессии не означает успешное завершение; авторитетный пустой список облачного избранного не восстанавливает старые удалённые записи из архива.

## Проверки и границы доказательства

59 автоматических проверок данных, приватности и регрессий пройдены локально. Действующие публичные карточки паттернов проверяются в браузере Work с реальным API сообщества. `tests/front-replay-isolated.html` использует настоящие модули фронта с отдельным пространством локального хранения и блокировкой внешних изменений: его записи не попадают в Supabase и продуктовые отчёты.

Авторизованный сквозной путь на настоящем iPhone, подключение Bluetooth-датчика и публикация личной заметки требуют действий владельца. Эти действия не объявляются проверенными без подтверждения. Отсутствующие исторические элементы экрана и потерянные события нельзя восстановить достоверно.

Откат: отменить коммит этой отдельной ветки; для серверной части вернуть предыдущие `index.ts`, `model.mjs` и состав файлов функции `setka-research-admin-v1`. Миграций схемы и удаления данных в этой доработке нет. Новые сохранённые слепки остаются совместимыми данными личного архива.

33 проверки настоящего API прошли после развёртывания: четыре выбранных исторических Replay содержат 562, 109, 1 272 и 29 игровых слепков, и все их рецепты разрешены. Проверены отказ без доступа, связь с проектом, отсутствие дублей, совпадение 3 сессий / 37 просмотров / 11 сохранений с текущими общественными агрегатами, неизменяемый кадр заметки, доступ к прежней админке и ленте модерации. Временный проверочный ключ API отозван; активных ключей этой проверки не осталось.

В браузере Work на опубликованной изолированной странице через настоящие кнопки пройдено: начало измеряемой сессии, запрос и состояние, RGB-паттерн, цвет, избранное, создание заметки, инструкция, смена паттерна, остановка, оценка после и завершение. В Replay видны паттерн, записанные кнопки и инструкция; Play, Pause, маркер сохранения и все шесть скоростей проверены. При проверке обнаружен и устранён повторный сбор касаний: новая запись повторно использует существующий единственный указательный регистратор. Подробный сбор требует включения пользователем и исключает защищённые формы.

Дополнительная браузерная проверка перехода после завершения выявила скрытую нижнюю навигацию над открытым экраном результата. Исправлено: навигация скрывается только при непосредственном просмотре паттерна, а завершение вызывает действующий пользовательский экран «Сегодня». Добавлена регрессия для этого случая.

Границы полотна: окно браузера на компьютере может быть шире самого приложения. Новые состояния сохраняют фактический прямоугольник приложения, и Replay рисует в нём с исходным отсечением. Исторический размер полотна не выводится из сегодняшнего CSS; его отсутствие помечается приблизительным. Повторный опубликованный путь «Закончить → Я → Заметки» пройден успешно. Полный CI завершился успешно в Chromium и WebKit; формы аккаунта в этом CI проверяются на изолированных ответах, не с настоящими паролями.
