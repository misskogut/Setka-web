# SETKA · функциональная ревизия фронта и исследовательской админки
Дата: 2026-10-21. Источник: GitHub main `6e99e0e4`, фронт `standalone-v34.html`, правильная админка `standalone-research-admin-v1.html`, агрегаты действующей БД setka-web-research.

## Что проверено фактически

- Production GitHub Pages: последний деплой main успешен **до** этой ревизии. Новый коммит проверяется отдельно.
- Live Supabase: `setka_research_v1_pattern_catalog` содержит 11 уникальных паттернов, включая Rain и Orbital Threads. Прочитаны только общественные агрегаты, никакие личные записи/ключи/пароли не читались и не изменялись.
- Live Supabase: `prototype_v41_config_metrics_current` на момент проверки содержит 2 конфигурации с подтверждёнными сохранениями (обе `spiral-snakes-3d`). Это **не равно** всему историческому архиву устройств и не повод удалять другие локальные записи.
- Исследовательская админка опрашивает сервер с интервалами 15/30 секунд, каталог фронта — около 30 секунд. Это реальное текущее поведение, не обещание realtime push.
- Изолированные тесты Chromium и WebKit: библиотека 11 паттернов, жесты, белый старт, девять цветов Orbital, динамические превью, два снимка заметок, сохранённые, сессия до/после, состояние, гостевая и аккаунтная память, два клиента, реальная цепочка фронт → смоделированный сервер → исследовательская админка, переименование паттерна, приглашения, Replay, имитированный BLE с явным тестовым источником. Все тестовые запросы отсекаются до production endpoints.

## Найденные дефекты и исправления в этой ветке

1. **Исследовательская админка ложно показывала «Данные получены», если запрос `catalog` завершался ошибкой, а `overview` проходил.** Теперь состояние `catalogError` сохраняется, статус «Данные неполные», в UI — уведомление о неподтверждённом каталоге. Ранее подтверждённые сведения остаются доступны.
2. **Сообщество принимало HTTP 200 без валидного массива `items` как подтверждённый пустой каталог.** Теперь отклоняет некорректный ответ; показывает «временно недоступно» или «ранее подтверждённые данные», без фиктивных нулевых карточек.
3. Новый тест `tests/setka-front-research-audit-browser.mjs`: реальная браузерная навигация по шести разделам исследовательской админки, сбой каталога → корректная индикация → восстановление, сбой публичной выдачи → корректная индикация → восстановление.

## Правила релиза

Никаких данных production не меняли. Изменения ограничены клиентскими сообщениями о статусе и тестами. Релиз допустим после зелёного `check-v34` в обоих браузерах, `check-research-admin-v1` и проверенного GitHub Pages deploy. Не выдавать автоматические тесты за проверку настоящего устройства.

Следующие системные приоритеты: согласовать серверные публичные метрики и видимость с актуальной БД; измерить задержку между front/server/admin; добавить версионные инкрементальные обновления и проверку reconnect; провести физический iPhone smoke и восстановление исторического архива без потери оригинальных записей.
