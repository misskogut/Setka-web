# SETKA — реальные помеченные аккаунты: проверенный этап 2
Дата: 2026-10-23. Полный сквозной аудит остаётся незавершённым.

## Решение владельца и результат
Владелец разрешил создать настоящие тестовые аккаунты в действующем проекте, пометить группу и позднее отключить её вклад вместо удаления.
Созданы test01–test10 через штатные invite/claim/set-password/login API.
Имена — серверные display_name; постоянные внутренние Tester ID сохранены.
Группа qa-e2e-20261023 сейчас active=true, include_in_metrics=true.
Пароли переданы отдельным приватным файлом; паролей, токенов и кодов в репозитории нет.

## Исправленная первопричина
Существующее active=false влияло на connected_accounts, но не исключало историю сохранений/сессий/просмотров из остальных агрегатов.
Новая общая серверная классификация setka_account_cohorts доступна только service_role.
setka_metric_accounts определяет единое множество: активный аккаунт с установленным паролем и разрешённым учётом.
На него ссылаются проекции сохранений, сессий, просмотров, опубликованных заметок и сохранений заметок.
Текущие service/pattern/config views используют эти проекции; публичные сценарии используют то же множество аккаунтов.
Research сохраняет все сырые данные, показывает имя/группу и исключает отключённые группы из текущей выборки.
Команда setka_set_cohort_state отзывает сессии при отключении. Guard выдачи сессий блокирует позднюю выдачу после отключения.
Никакой проверки по префиксу test в потребителях; решение применяется к любой следующей серверной группе.

## Как видеть и позже отключить группу
Исследовательская админка → Участники → группа qa-e2e-20261023.
После отключения группа остаётся доступна через выбор её имени, даже если исключена из текущих KPI.
Кнопка «Отключить группу и исключить из показателей» вызывает существующий admin-auth API, не локальное переключение.
Авторизованный браузерный просмотр этой кнопки и списка пока НЕ проверен: требуется действующий ключ администратора в защищённой форме входа.
Вход в тестовые кабинеты — по отдельным постоянным Tester ID и паролям из приватного файла.
Текущее ограничение устройства: один профиль браузера закреплён за одним Tester ID. Для разных аккаунтов использовать отдельные профили/свежие приватные сессии; профиль настоящего аккаунта не очищать.

## Что ещё не пройдено
- Авторизованный браузерный проход всех 10 пользователей и настоящего аккаунта владельца.
- Несколько полноценных сессий каждого пользователя с реальным просмотром и реплеем.
- Модерация и последующее публичное распространение заметки test07.
- Три новых принципиально разных тестовых алгоритма, их удаление и восстановление в изолированном каталоге.
- Конкурирующие конфигурации и полная модель ревизий двух клиентов.
- p50/p95 сквозной синхронизации; записанные времена отдельных HTTP-ответов не являются таким измерением.
- Физические iPhone/Android/BLE/микрофон.
- Две ранее найденные legacy-таблицы с отключённым RLS остаются отдельной открытой находкой; их права этим этапом не менялись.

Завершён этап создания и серверного управления настоящей тестовой группой; полный аудит SETKA не объявляется завершённым.
