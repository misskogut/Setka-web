# SETKA Standalone v34 · ревизия связности данных и поведения
Дата: 2026-10-09 · Ветка: fix/v34-pattern-notes-integrity-20261009
Статус: **TESTED IN CHROMIUM / iPHONE SAFARI NOT YET VERIFIED**. Основной `standalone-v34.html` не заменять до пользовательской проверки.

## 1. Принцип доказательств
- SOURCE-CHECKED: фактически прочитаны JS-файлы, SQL определения представлений и серверная Edge Function.
- DATA-RECONCILED: агрегированные показатели v41 повторно вычислены независимым SQL на записях.
- BROWSER-TESTED: Playwright/Chromium с отдельными искусственными значениями облачных метрик, без реальных пользовательских данных; семь ID, семь canvas, семь превью и семь привязок облачных чисел.
- NOT-PROVEN: настоящий ввод на iPhone Safari, аппаратный пульсометр, реальные пользовательские логины и операции администратора, полный облачный жизненный цикл заметки с сервером.

## 2. Исправлено в рабочей ветке
1. Отдельный старый обработчик `standalone-methodology-v34.js` всегда показывал Tentacle Orbit независимо от выбранной плитки. Отключён.
2. Захват `pointerup` материнской плиткой скрывал касание ⓘ на мобильном. Исправлено.
3. Мелкое превью Stereo DNA становилось почти чёрным из-за субпиксельного размера точек. Исправлено.
4. Заметки выбирались по совпадению текста и времени, а не по immutable `note.id`. Исправлено; при создании связываются `patternId`, `config`, `frame` и визуальный рецепт.
5. Вкладка Notes могла заменяться библиотекой паттернов при повторном рендеринге. Исправлено.
6. Облачные показатели `prototype_v41_pattern_metrics_current` смешивались с локальными и могли опережать загрузку. Источники теперь разведены, пустые данные объяснены.
7. Источником сценариев был локальный `topIntents`, но при наличии облачной сводки этот блок полностью пропадал. Теперь виден **отдельный блок личных сценариев**, один раз на сессию для одного паттерна.
8. Измеряемое время прекращало учитываться после 30 секунд без касаний. Это неверно для пассивного просмотра. Счётчик теперь учитывает только активный видимый игровой экран; при наложениях, смене раздела и скрытии вкладки время паузится.
9. В допустимых конфигурациях `backgroundAlpha=0` и `baseRadius=0` заменялись значениями по умолчанию из-за `||`. Исправлено.
10. Незаданные `preState`/`postState` трактовались как числовой ноль в наблюдениях и ранжировании. Исправлено.
11. Рекомендации рассматривали только Tentacle Orbit как базовый паттерн. Теперь выбирают среди семи и не приписывают разницу самооценки всем паттернам в смешанной сессии.
12. Запуск сессии и открытие конфигурации явно передают `patternId` вместе с `config`, предотвращая неявные подмены.

## 3. Результаты независимой сверки с Supabase
Для всех строк `prototype_v41_pattern_metrics_current` независимый SQL повторно подсчитал экспозиции, различные сессии, миллисекунды и уникальные аккаунты, сохранившие паттерн. Все 3 строки совпали с view:
- `tentacle-orbit` — 25 эпизодов / 2 сессии / 83 505 мс / 1 аккаунт сохранил.
- `dandelion` — 12 эпизодов / 2 сессии / 44 408 мс / 1 аккаунт сохранил.
- `breathing-fractal` — 0 эпизодов / 0 сессий / 0 мс / 1 аккаунт сохранил.
Остальные 4 базовых паттерна сейчас **отсутствуют в текущем v41-представлении**, потому что в подключённой выборке нет их просмотров или сохранений. Отсутствие записи != отсутствие использования всеми пользователями.

## 4. Почему пропало «Чаще используют для»
Ранее отдельная `setka-pattern-insights` Edge Function могла вернуть `topIntents` через исторические `sessions.request_key`.
Нынешняя v41 Edge Function `setka-community-patterns-v38` читает только просмотры/сохранения/длительность и **не передаёт целей сессий**: схема `prototype_v41_account_exposures` не содержит `request_key`.
Локальные private `patternExposures` могут иметь `requestKey`; в карточке он доступен как **«По каким сценариям ты используешь паттерн»**, на основании уникальных `sessionId`.
В архиве v35 найдено 238 эпизодов `dandelion + sleep` из трёх сессий: подсчёт «238 просмотров сна» был бы серьёзным искажением. Нельзя механически смешивать историческую выборку v35 и живую выборку v41 или превращать архивные private-сценарии в общедоступную аналитику без отдельного решения по согласию.

## 5. Автоматизированные проверки
Workflow `Check SETKA Standalone v34`, `node --test tests/standalone-v34-integrity.test.mjs` и `tests/standalone-v34-browser-smoke.mjs`.
- Все 7 canvas и их диалоги ⓘ отображаются с правильными идентификаторами и различающимися mock-цифрами.
- 70 эпизодов, относящихся к 3 сессиям, показывают 67%/33% по числу сессий, а не долям от жестов.
- Две заметки с одинаковым текстом на Dandelion и Stereo DNA имеют разные immutable IDs, правильные `replaySnapshot.patternId` и `config.patternId`.
- Статические регрессии: невалидные/нулевые параметры, время пассивного просмотра, скрытие overlay, null-feedback, семь базовых паттернов в рекомендациях.

## 6. Обязательные оставшиеся проверки
- iOS Safari и WebKit: физические тапы, масштаб миниатюр, полные сценарии выбора/времени, сохранение, перезагрузка.
- Реальная авторизованная синхронизация заметки между устройствами и её предпросмотр после reload, включая добровольную публикацию.
- Платформа администратора (полномочия, модерация, отчёты и действия). Синтаксис проходит, но end-to-end проверка не выполнена.
- Настоящее BLE-устройство, физические потоки HR/RR; нет разрешения на имитацию реальной физиологии.
- Продуктовое решение об агрегировании сценариев по аккаунтам: явный источник и согласие, без утечки индивидуальных запросов.
- Миграция старых заметок с повреждёнными метаданными: точное восстановление без доказательств исходной конфигурации невозможно.
