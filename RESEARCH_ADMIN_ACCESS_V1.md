# SETKA Research 1.4.9 · существующий доступ владельца

Родитель: 28a0be85e3dd3d3051c36a14d2e73785757a103c.

Владелец сообщает, что ключ не принимают обе админки. Журнал действующего API
содержит отказы 403 около 23:44–23:46 по Саратову. Новая и прежняя админки проверяют
один реестр `admin_keys`; текущий сервер отвечает, в реестре есть активные ключи.
Какой именно сохранённой записи соответствует введённый вариант, без секрета
не установлено. Введённый ключ не запрашивается, не извлекается и не записывается.

## Исправление

- Новая страница поддерживает существующие `owner_ticket` и `#access` прежней
  админки. Используется только действующий `setka-admin-owner-recovery-v1`.
  Параметры удаляются из адреса до запросов данных. Разовый билет погашается
  только по явной кнопке; полученный доступ всегда проверяется основным API.
- Билет владельца имеет приоритет перед устаревшими копиями ключа. Перезагрузка
  использует проверенный доступ; использованный билет не погашается повторно.
- Отказ localStorage/sessionStorage не превращает успешную серверную проверку
  в ошибку входа. Вход остаётся в памяти страницы с понятным предупреждением.
  Смена способа запоминания очищает обе устаревшие копии. Ошибка адреса, отказ
  ключа и истёкшая ссылка имеют разные сообщения.
- Схема БД, серверная проверка, ключи других администраторов, старая полная
  админка, фронт и музыкальные режимы не меняются. Новый способ выдачи прав
  не создаётся. Обход проверки ключа отсутствует.

## Проверка и ограничения

Модульные и изолированные браузерные проверки покрывают успешное восстановление,
неверный ключ, истёкший билет, заблокированное хранилище, приоритет нового доступа,
перезагрузку и отсутствие доступа к данным до серверной проверки. В них используются
только фикстуры, запросы к рабочему Supabase перехватываются.

Рабочую ссылку восстановления погашает сам владелец. Нельзя объявлять вход на его
физическом iPhone подтверждённым до его действия. Секретные значения не включаются
в исходники, PR, отчёт или снимки экрана.

Откат: вернуть `research-v1/app.mjs` и HTML к родителю. Серверные права и данные
не менялись; существующий вход в прежнюю админку остаётся независимым.
