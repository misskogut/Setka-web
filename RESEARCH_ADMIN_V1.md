# SETKA Research Admin 1.0

Новая добавочная линия исследовательской админки приложения с паттернами.
Исходная точка: `9a1530f1c145d2925ad8517b33b127c884948035`.
Рабочая ветка: `research/admin-v1-20261013`.
Страница: `standalone-research-admin-v1.html`.
Supabase: `gfchgaphzhxufwdhrcis`.
Прежняя полная админка: `standalone-admin-v34.html` — файл и зависимости не изменены.
Фронт: `standalone-v34.html` — файл и зависимости не изменены.
Это отдельная линия приложения; Diamond, Foundation runtime, Genesis и Верстак не перенесены в навигацию.

## Шесть разделов

1. Главная: период, текущий/исторический источник, 12 кликабельных показателей, динамика, активность, диагностические переходы.
2. Сессии и Replay: измеряемые сессии, отдельные визиты, отдельно архивные фрагменты; поиск, паттерн, результат, телефон, пауза, перемотка, ×0,5/1/2/3/4/8, реальные маркеры.
3. Участники: подтверждённая идентичность, сессии, просмотры, заметки, сохранения, симптомы, согласие, инвайты и только реальные физиологические измерения.
4. Паттерны: семь живых превью, общие показатели, точные конфигурации, длительность/медиана/повторы, сессии, заметки, самооценки и публичные варианты.
5. Сообщество: конфигурации, публичные заметки, модерация, сохранённые решения. Личные материалы автоматически не публикуются.
6. Исследования: пары оценок, размер выборки, поведение, сравнение конфигураций, объяснение существующего правила, серверные планы экспериментов с историей и восстановлением предыдущего плана.

## Источники и границы достоверности

Текущие общественные показатели: `prototype_v41_account_sessions`, `prototype_v41_account_exposures`, `prototype_v41_account_favorites`; контрольная сверка — v41 current views.
Продолжительность считается по PatternExposure, не по Replay и не по общему времени пребывания в приложении.
Текущие канонические аккаунтные просмотры имеют приоритет над всеми их архивными/legacy копиями.
Записи разных устройств объединяются только по существующему аккаунту и подтверждённой привязке.
Общая историческая метка `yulia` не подтверждает, что устройства принадлежат одному человеку.

На момент проверки: 1 текущий аккаунт, 3 сессии, 37 просмотров, 11 сохранений.
Исторические данные: 98 устройств, 67 снимков, 26 индексных сессий, 67 визитов, 6003 сводки Replay.
6003 сводки не означают 6003 визита: 5981 из них — архивные фрагменты свободного просмотра.
RAW в активной таблице: 0; в отдельном сохранённом архиве: 50455 событий.
Часть сводок содержит больше событий, чем сохранилось в разворачиваемом архиве — полнота не выводится из счётчика сводки.
145 явно помеченных имитированных измерений пульса исключены из реальной физиологии.

Новая функция `setka-research-admin-v1` читает `prototype_v34_raw_events_all_v2`: активные + архивные события.
К уже существующему серверному service_role добавлено только чтение специализированного RAW-архива и выполнение его security-invoker функции.
Публичным и пользовательским ролям эти права не выданы. RLS и исходные источники не изменены.

Replay всегда показывает полноту. Полная допустима только при явном подтверждении покрытия рекордером.
При неизвестном начальном состоянии экран остаётся неизвестным до первого зарегистрированного слепка.
Пиксельная запись отсутствует: паттерн перерисовывается по параметрам и кадру. Неизвестный viewport, несовместимая версия, кадровый след и пропущенные действия ограничивают точность.
Экран библиотеки/формы без сохранённых подробностей показывается как зарегистрированный переход с пояснением, без выдуманных карточек.
Несохранённая конфигурация может иметь канонический ID без визуального рецепта; это явно показано.

## Защита

Повторно используется существующий `admin_keys` контракт SHA-256 + active.
Новый endpoint не выдаёт ключи, пароли, session tokens или способы восстановления входа.
Только публичный publishable key находится в клиенте; service role остаётся в окружении Supabase.
Доступ проверяется сервером перед каждой операцией. CORS ограничен GitHub Pages владельца.
Ответы приватные/no-store. HTML имеет CSP; пользовательские строки экранируются.
Продуктовые чтения не пишут в базу. Модерация — через прежний контролируемый API.

Новые экспериментальные таблицы RLS включены, anon/authenticated не получают чтение или запись.
RPC сохранения — SECURITY INVOKER, service-only; обновление и версия сохраняются одной транзакцией с проверкой revision.
Это реестр планов, без назначения людей в группы или изменения чувствительных правил.
Рабочая база не заполнялась тестовыми планами.

Существующий Supabase security advisor обнаруживает исторические SECURITY DEFINER views и две агрегатные legacy таблицы без RLS.
Они не создавались новой версией; массовая смена их прав не выполнялась. Отдельная ревизия требуется перед расширением аудитории.

## Проверка

`node --test tests/research-admin-v1.test.mjs` — изолированные инварианты без живых записей.
Регрессии прежней админки, общественных агрегатов и неизменяемых заметок также проверены.
`tests/research-admin-v1-live-smoke.mjs` — реальные API, существующая авторизация, отказ без ключа, чужой Origin, API старой админки, источники, сверка метрик, Replay, конфигурация заметки.
Ключ подаётся через скрытый stdin. Временный хэш ключа проверки отзывается после проверки; секрет не сохраняется.
`tests/research-v1-ui.html` — отдельная синтетическая проверка UI плеера, без сети/пользовательских записей/записи в базу. Она не подключена к продуктовой странице.
Браузерные доказательства и незавершённые проверки фиксируются в `research-v1/verification.json`.

Без входа владельца нельзя подтвердить защищённый путь целиком в браузере.
На настоящем iPhone/Safari нужно проверить касания, прокрутку, восстановление после сворачивания и приход нового действия во фронте.
Положительное решение модерации нельзя тестировать на чужой публикации; текущая очередь пуста.
Для проверки сохранения плана нужен настоящий план владельца, а не синтетическая запись в рабочих отчётах.

## Откат

Исходная админка и фронт не зависят от новой страницы или endpoint.
Переход на исходную админку немедленно возвращает прежний интерфейс.
Откат новой страницы выполняется отдельным коммитом; исходные страницы не заменяются.
При отключении нового архивного чтения можно отозвать только два добавленных service-role права, см. SQL.
Новые планы и append-only версии при откате сохраняются. Таблицы с написанными владельцем планами не удаляются.
Серверные SQL-изменения сохранены в Supabase migration history и воспроизводимы по SQL в `research-v1/sql/`.
