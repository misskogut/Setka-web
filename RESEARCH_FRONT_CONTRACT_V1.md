# SETKA · фронт и исследовательская админка · 1.4.0

Родитель: `c03a2c5533289d876e68ca88f43c25d07e10e911` (1.3.0).
Только мобильная SETKA с визуальными паттернами. VERSTAK и прежняя полная админка независимы.

## Обязательное правило для последующих изменений

Любая новая функция проходит полный путь «фронт → сервер → админка». Источник, устойчивый ID,
доступ, реальный результат записи и чтения проверяются совместно. Декоративных кнопок и счётчиков нет.
Неизвестные данные показываются как неизвестные, исторические свидетельства не удаляются.

## Пульс и зарегистрированные действия

Настоящий Bluetooth Heart Rate Measurement сохраняет `observedAt`, сессию, визит, exposureId,
patternId, версию, configKey, числовой слепок конфигурации и кадр в момент измерения.
Перед слепком текущая конфигурация сверяется с renderer state: прежние настройки не подставляются
в измерение, полученное во время жеста. Открытая карточка, инструкция и скрытое приложение не
считаются просмотром паттерна. Время — время получения пакета браузером, не независимые часы датчика.

Показания сопоставляются с одним подтверждённым участником, устройством, сессией, конфигурацией
и полуоткрытым временным интервалом. Отсутствующий или неоднозначный просмотр остаётся неизвестным.
Исторические demo/simulated/непроверенные показания не входят в анализ.
Исправлены фильтр периода (раньше не передавал physiology в исследовательский экран) и исследовательский
bridge (раньше присваивал каждому варианту среднее пульса сессии и приблизительное число измерений).
Теперь contribution использует только реальные пакеты внутри точного интервала usage конфигурации.

`standalone-activity-v1.js` сохраняет наблюдаемые интервалы (до 15 секунд) с фактическим числом
нажатий на поверхность паттерна, записей движения (не чаще 5/сек) и изменений настроек.
Это ввод в приложении, не измерение двигательной активности тела. «Без касаний» допустимо только
при coverage=observed; отсутствие старого журнала не превращается в спокойный просмотр.
События Replay продолжают сохранять реальные зарегистрированные жесты по существующему договору.
В Replay показано последнее реальное измерение не старше 15 секунд с его собственным временем.
График не соединяет большие пропуски; кривые разных людей не объединяются.

Новые интервалы и история первых открытий проходят существующий приватный облачный архив;
на гостевом устройстве остаются локальными. Существующие согласия, ограничения ввода и права доступа
сохранены. Новые признаки не меняют чувствительные правила рекомендаций автоматически.

## Общие названия паттернов

Источник: `setka_research_v1_pattern_catalog`; история: `setka_research_v1_pattern_names_history`.
Базовые семь записей соответствуют действующим renderer IDs. Рецепт, версия и ID при переименовании
не меняются. Админка: «Паттерны → карточка → Название в приложении». Изменение требует действующего
административного доступа и ожидаемой версии записи. Конкурирующее изменение возвращает conflict.
Восстановление прежнего названия создаёт новую версию, не удаляет историю.
Публичный action=catalog возвращает только ID, название, revision и время; никаких личных строк.
Фронт читает каталог на старте, при возврате и каждые 30 секунд видимой работы.
Все пользовательские названия экранируются перед вставкой в HTML.

## «Новый» до первого открытия

Метка на базовом превью зависит от openedPatterns и уже зарегистрированных открытий/просмотров
этого пользователя. Просмотр превью и сохранение конфигурации не подменяют открытие.
После фактического pattern-open метка исчезает; история синхронизируется между подтверждёнными
устройствами аккаунта. Новый зарегистрированный renderer ID автоматически получает свою метку.
При переименовании старый ID остаётся прежним: метка заново не появляется.

## Пригласительные ID и рефералы

Используется существующий одноразовый claim-code и постоянный Tester ID; вход не заменён.
Фронт: «Я → Аккаунт → Пригласить в SETKA». Админка: «Участники → Пригласительные ID и рефералы».
Можно выдать один ID или именованный пакет; большой запрос выполняется порциями по 100.
Пакет хранит запрошенное количество; журнал показывает отдельно действительно созданные ID,
принятые приглашения и аккаунты с заданным паролем. Число выданных ID не считается числом пользователей.

Источники: existing `prototype_v34_tester_codes` с тремя добавленными полями,
`setka_research_v1_invite_batches`, `setka_research_v1_invite_requests` и service-only view
`setka_research_v1_invites`. Автор берётся из проверенной серверной сессии/административного ключа,
не из произвольного ID запроса. Участник видит только выданные своим аккаунтом приглашения;
администратор видит весь журнал и точные связи с принявшим ID. Старые локальные инвайты остаются
историческими и не считаются серверными приглашениями.

Транзакция сохраняет пакет и коды атомарно. Идентификатор запроса защищает от повторной выдачи.
На сервере хранятся только хэши одноразовых кодов; открытые коды нужно скопировать/скачать до
закрытия экрана. После обрыва проверяют журнал и сохраняют полученную часть перед новой выдачей.
SQL RPCs SECURITY INVOKER, вызов только service_role из существующих авторизованных Edge Functions.
Новые таблицы закрыты RLS и отзывом прямых grants у public/anon/authenticated.

## Проверки и ограничения

Контрактные тесты: идентичность/временные границы/полнота/фильтр периода/точные пульсовые вклады,
ввод и хэширование приглашений. PostgreSQL CI проверяет реальные транзакции, историю переименования,
conflict, владельца пакета, защиту повторного запроса, 100+1 ID и связь активации с рефералом.
Изолированный браузерный сценарий Chromium/WebKit проверяет две UI части, имена/метку, приглашения,
пульс и действия. Все внешние API в этом сценарии перехвачены; синтетические записи не идут в Supabase.
Отдельно после публикации проверяются действующий публичный каталог и закрытость защищённых API.
Физический пульсометр и браузер на настоящем iPhone не доступны этому исполнителю и не объявляются PASS.
Рабочие ID и имена не меняются ради теста: владелец проверяет авторизованные действия на своих данных.
